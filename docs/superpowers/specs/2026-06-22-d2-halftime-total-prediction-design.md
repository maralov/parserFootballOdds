# Спека D2: HT-прогноз підсумкового тоталу матчу

**Дата:** 2026-06-22 · **Гілка:** v4.1 · **Статус:** draft на рев'ю · **Підпроєкт:** D2 (з пари D1+D2)

## Контекст і feasibility

Новий прогноз: **на перерві (45') оцінити підсумковий тотал матчу** з HT-рахунку, 1H-стати,
прематч-кефів і LLM-контексту. Розвідка виявила обмеження:
- **Фінальних результатів немає** (0/301), трекінг зупиняється на HT (1H-only) → потрібна нова
  інфраструктура для мітки.
- **Кефи лише 1X2** (home/draw/away), тоталів немає → старт **без ROI**, лише точність.
- **Немає історії** → D2 не валідується на минулому; збираємо й прогнозуємо паралельно, оцінка ~через 2 тижні.

## Цілі / Non-goals
**Цілі:** на HT видавати `P(тотал≥2)`, `P(тотал≥3)`, очік. голи + впевненість для матчів, у які ми
вже зробили 1H-прогноз; дотрековувати фінал для валідації; збирати ознаки для майбутньої стат-моделі.
**Non-goals:** ставки/сигнали (поки лише запис прогноз+результат); тотал-кефи/ROI (Фаза B);
розширення скоупу поза 1H-прогнозовані матчі.

## Скоуп матчів
**Лише матчі, для яких зроблено 1H ТМ/ТБ-прогноз** (тобто detailed + xG-зона з D1). HT-прогноз
тоталу йде «зверху» на ту ж вибірку — без додаткового відбору матчів.

## Дизайн

**1. 2H→FT трекінг (дані).** Після HT матч лишається в трекінгу на **рідкій каденції (раз на 10-15 хв)**
до фінального свистка; пишемо `final` (рахунок) + грубі 2H-снепшоти. Нові флаги
`LIVE_2H_TRACK_TO_FT` (bool) + `LIVE_2H_POLL_MIN` (15). Резолюція 1H-ліній на HT — без змін.

**2. HT-предиктор `runHtTotalDecision`.** Тригер — резолюція 1H-прогнозу на перерві (для матчів зі
скоупу). Вхід: HT-рахунок, 1H-cumulative (xG/удари/SoT/володіння), прематч 1X2+фаворит, таблиця.
Виклик LLM з **новим промптом** (нижче). Вихід → `predictions.htTotal`:
`{ expGoals, pOver15, pOver25, confidence, reasoning, keySignals, foundFactors, decidedAt }`.

**3. Лог ознак.** Поряд із прогнозом зберігаємо сирі 1H-ознаки (HT-рахунок, 1H-xG/удари/SoT/володіння,
фаворит, кеф нічиєї) → для майбутньої статистичної baseline-моделі і порівняння з LLM.

**4. Резолюція.** Прийшов `final` → фактичний тотал = сума голів матчу → закриваємо htTotal:
`over15Hit = total>=2`, `over25Hit = total>=3`. Записуємо в `predictions.htTotal.outcome`.

**5. Оцінка.** Розширити аналітику: точність по кожній лінії, калібрування (p→факт), Brier-score,
розбивка за HT-рахунком і 1H-xG. Без кефа — точність/Brier; ROI — Фаза B (коли додамо тотал-кефи).

## LLM-промпт (provisional базові орієнтири)
Системний промпт: прогноз тоталу на HT, якір на помірно-низьку базу (матчі малорезультативні),
2H зазвичай результативніший за 1H; HT-рахунок додається; низький 1H-xG → UNDER. web_search за
сильними факторами (ігрова ситуація 2H/мотивація, склади/заміни, червоні, погода, характер ліги);
слабкі сигнали (загальні H2H/володіння) не роздувають p. Калібрування: без сильного фактора →
біля бази, confidence ≤0.40. Вихід STRICT JSON: `expected_goals, p_over_1_5, p_over_2_5,
confidence, reasoning, key_signals[], found_factors`. (Повний текст — у [oneH_Prompt.js](../../../src/ai/prompts/oneH_Prompt.js)-стилі, новий файл `htTotal_Prompt.js`.)

## Фазування
- **Фаза A (зараз):** 2H→FT трекінг + `runHtTotalDecision` + резолюція + лог ознак. Прогнозуємо й
  збираємо паралельно. Без ставок.
- **Фаза B (~через 2 тижні):** оцінити точність/калібрування, вибрати лінію (1.5 чи 2.5), опц. стат-модель,
  додати джерело тотал-кефів → ROI і (можливо) сигнали.

## Тести (TDD)
- 2H→FT: після HT матч лишається active до minute≥90/FT; пише `final`; каденція ~15 хв.
- `runHtTotalDecision`: тригер лише для матчів зі скоупом (є 1H-прогноз); парсинг LLM-виходу; запис htTotal.
- Резолюція: final 2:1 → total=3 → over15Hit=true, over25Hit=true; 0:0 → обидва false.
- Промпт містить база-якір + якісний пошук (assert ключових фраз).
- Idempotency: повторний HT-виклик не дублює.

## Ризики
- Старт «наосліп» (нема історії) — перші ~2 тижні лише збір/оцінка, не довіряти прогнозам.
- Скоуп упереджено малорезультативний (0:0-кандидати) — тотал-база нижча за середню; врахувати в оцінці.
- Базові орієнтири промпту provisional — калібрувати з зібраних фіналів (Фаза B).
- 2H→FT трекінг додає навантаження (хоч і рідке) — стежити за лімітами фетчера.
