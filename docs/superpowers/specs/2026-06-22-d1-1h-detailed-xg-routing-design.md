# Спека D1: 1H ТМ/ТБ на detailed з xG-роутингом

**Дата:** 2026-06-22 · **Гілка:** v4.1 · **Статус:** draft на рев'ю · **Підпроєкт:** D1 (з пари D1+D2)

## Контекст

Бектест 5 тестових днів (06-18…06-22, 263 чисті 0:0-кандидати) показав:
- на 27' результат ≈ монетка (DRY 49%), і груба статистика (SoT/удари/володіння/кутові) **не передбачає** його;
- edge сконцентрований у **detailed-лігах** і **лайв-xG**: ТМ наосліп −15% → ТМ на detailed +6% → ТМ на detailed+xG≤0.15 **+33%** (HR 75%); ТБ-edge — у «будівельній» xG-зоні;
- модель **перевпевнена** (заявлений p=0.65–0.75 vs реальний HR ~50%).

D1 переносить цей edge у движок: фокус **лише на detailed**, напрям обирає **лайв-xG**.

## Цілі / Non-goals
**Цілі:** підняти HR ТМ/ТБ через xG-роутинг на detailed; прибрати ставки в зонах-монетках.
**Non-goals:** basic-ліги (лишаються тільки для трекінгу базової статистики, без AI/ставки); реальні кефи від букмекерів; D2 (HT-прогноз на весь матч — окремий спек).

## Дизайн

Зміни в [runOneH_AiDecision.js](../../../src/prediction/runOneH_AiDecision.js):

**1. Гейт `statsLevel=detailed` — ПЕРЕД AI-викликом.** basic → рання зупинка (без LLM, економія API); матч усе одно трекається й резолвиться (htOutcome) для базової статистики.

**2. Роутинг напряму за лайв-xG** (сума `cumulative.expectedGoalsXg` зі снепшота на момент рішення; замінює поточне `favorite?over:under`):
| лайв-xG@рішення | напрям | очікування (5 днів) |
|---|---|---|
| ≤ 0.15 (мертвий матч) | **ТМ** (under) | ~85% dry |
| 0.15 – 0.50 («будує») | **ТБ** (over) | ~36–60% гол, медіана 34–35' |
| > 0.50 або xG відсутній | **skip** (фаза `skipped_by_xg`) | шум / малі n |
Пороги **provisional** (мала вибірка) — винести в конфіг, калібрувати з даними.

**3. Новий LLM-промпт** ([oneH_Prompt.js](../../../src/ai/prompts/oneH_Prompt.js)) — база-якір + якісний пошук (склади/мотивація/погода/характер), забороняє роздувати p зі слабкої статистики. Анкер базової ставки: ~60% dry (detailed). LLM працює **всередині** обраної xG-зони.

**4. Запобіжники лишаються** (підтверджено користувачем): `p≥LIVE_1H_MIN_P` (0.50) floor + consensus flip/skip. Примітка: тепер напрям задає сильний xG-прайор, тож flip проти xG-зони має бути рідкісним; якщо дані покажуть, що flip шкодить — звузити consensus до skip-only.

**5. Без EV-фільтра по кефу** (за рішенням користувача «не фільтрувати — кеф лише для ROI»): хардкод-мапа [oddsTable.js](../../../src/scoring/oddsTable.js) пише `odds` у прогноз для обліку тестового ROI, але **не гейтить** ставку. Гейт = detailed + xG-зона + LLM(p-floor, consensus).

## Порядок гейтів (новий)
`statsLevel=detailed?` → `xG-зона (ТМ/ТБ/skip)` → AI(p, confidence, signals для обраного напряму) → consensus(flip/skip) → p-floor → запис прогнозу (odds лише для ROI) → confirm/goal-race → signal.

## Конфіг (нові)
| Флаг | Дефолт | Призначення |
|---|---|---|
| `LIVE_1H_DETAILED_ONLY` | true | Гейт лише detailed перед AI |
| `LIVE_1H_XG_UNDER_MAX` | 0.15 | xG ≤ → ТМ |
| `LIVE_1H_XG_OVER_MAX` | 0.50 | xG у (UNDER_MAX, OVER_MAX] → ТБ; вище → skip |

## Тести (TDD)
- xG-роутинг: ≤0.15→under, 0.30→over, 0.70→skip, xG=null→skip; basic→рання зупинка без AI.
- Запобіжники працюють поверх xG-роутингу (p<0.5→skip; high goal-leaning на ТМ→flip/skip).
- Промпт містить база-якір + інструкції якісного пошуку (assert на ключові фрази).
- Регрес на 06-18…06-22 через бектест-скрипт: ТМ(detailed+xG≤0.15) відтворює ~75% HR.

## Поведінковий вплив / ризики
- Обсяг різко впаде (лише detailed + xG-зони): ~3–18 ставок/день. Навмисно.
- xG-пороги на малій вибірці (n=15–16 у ключових зонах) — **provisional**, калібрувати.
- Залежність від наявності лайв-xG у снепшоті detailed (підтверджено: 309/312 мають стату, xG у detailed).
